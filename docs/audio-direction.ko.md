# Pawblossom Puzzle 오디오 방향과 연결 안내

## 현재 구현

`src/audio/AudioManager.ts`의 `export class AudioManager`는 원본 Web Audio API만 사용하는 독립 모듈입니다. 외부 음원, 서버, API 키, 음악 다운로드, Phaser 오디오 플러그인에 의존하지 않습니다. 설정 기본값은 음악·효과음 모두 켜짐이며 실제 소리는 사용자 입력에서 `unlock()`을 호출한 뒤에만 시작됩니다.

| API | 동작 |
| --- | --- |
| `async unlock(): Promise<void>` | 클릭·탭 콜백에서 직접 호출합니다. 컨텍스트를 지연 생성하고 재생을 허용합니다. 미지원 환경이나 resume 실패는 게임을 중단시키지 않으며 후속 사용자 입력에서 재시도할 수 있습니다. |
| `setMusicEnabled(enabled: boolean): void` | BGM 설정과 버스 음량을 변경합니다. 꺼지면 음악 스케줄러와 예약된 음악 음성을 정리합니다. |
| `setSfxEnabled(enabled: boolean): void` | 효과음 설정을 변경하고 꺼지면 효과음 음성을 정리합니다. |
| `readonly musicEnabled / sfxEnabled: boolean` | getter로 현재 설정을 읽습니다. 저장은 호출 측에서 담당합니다. |
| `play(name: SoundName, chain = 1): void` | `tap`, `swap`, `invalid`, `match`, `special`, `win`, `lose`, `reward`를 합성합니다. 잠김·일시정지 중의 효과음은 누적하지 않습니다. |
| `suspend(): void` | 명시적 일시정지. 음악 타이머, 예약 음성과 효과음을 정리하고 컨텍스트를 멈춥니다. |
| `resume(): void` | 명시적 일시정지를 해제하고 이미 unlock된 컨텍스트를 복귀시킵니다. 모바일 정책 때문에 추가 사용자 입력이 필요할 수 있습니다. |
| `destroy(): void` | 리스너·타이머·노드·컨텍스트를 정리합니다. 여러 번 호출해도 안전하며 이후 unlock으로 재사용하지 않습니다. |

```ts
import { AudioManager } from './audio/AudioManager';

const audio = new AudioManager(); // 앱 전체에서 하나를 공유
// 실제 pointer/click 핸들러 안에서 호출해야 합니다.
async function onStartPressed() {
  await audio.unlock();
  audio.play('tap');
}
audio.play('match', 3); // 연쇄 3단계의 매치 처리 시점
audio.setMusicEnabled(false);
// Capacitor App appStateChange: inactive -> suspend(), active -> resume()
// 광고 표시 직전 -> suspend(), 종료/실패 콜백 -> resume()
// 앱 소유자의 최종 종료 시 -> destroy()
```

위 코드는 호출 예시이며 앱이나 Capacitor 이벤트에 자동 연결된 코드는 아닙니다. 초기 설정을 저장소에서 읽어 setter에 전달하고, 변경할 때 저장해 주세요. `document.visibilitychange`는 내부에서 처리합니다. 브라우저 복귀는 자동으로 재시도하지만 명시적인 `suspend()` 상태는 `resume()` 전까지 유지합니다. 배경 전환과 광고 일시정지가 겹치면 앱 측에서 일시정지 이유들을 관리해 모든 이유가 해제된 뒤에만 `resume()`을 호출해 주세요.

Phaser 장면 전환마다 새 인스턴스를 만들지 않습니다. 이 모듈은 자체 컨텍스트를 사용하므로 Phaser의 오디오 잠금 해제와 별도로 `unlock()`을 호출해야 합니다. 숨김에서 복귀하면 BGM을 첫 마디부터 다시 시작하고 오래된 효과음은 재생하지 않습니다.

## 음색과 직접 작곡한 루프

- BGM은 72 BPM, 4/4, 8마디 약 26.67초의 직접 작성한 단순 선율입니다. C 장조 5음계 C·D·E·G·A만 사용합니다. C/A/G 중심의 저음과 5도음을 성기게 놓고 마지막 마디의 쉼으로 루프에 여유를 줍니다.
- 실제 피아노 샘플이 아니라 기본 사인파와 약한 2배음, 짧은 어택·감쇠로 만든 피아노/마림바를 연상시키는 합성음입니다. 동물 목소리·자연 환경음은 아직 없습니다.
- `match`의 chain은 유한한 정수 1~8로 보정합니다. 단계마다 5음계 안에서 올라가되 고음과 음량을 무한히 높이지 않습니다. 실패는 작은 하행 음형으로 표현하고 불안감을 주는 경고음을 피합니다.

## 재생 안정성과 음량

컨텍스트의 `currentTime`을 기준으로 25ms마다 다음 180ms를 예약합니다. 루프마다 타이머를 다시 시작하지 않고 연속된 노트 시간에 8분음표 간격을 더합니다. 바쁜 프레임에서 놓친 음은 건너뛰어 몰아 재생하는 현상을 막습니다. 배경·운영체제 중단 때 예약 음을 정리하고 재생 가능한 running 상태에서만 다시 예약합니다.

음성은 예약된 음까지 포함해 BGM 6개, SFX 14개로 제한합니다. 한 음성당 오실레이터 2개이므로 최대 40개입니다. 같은 종류의 효과음을 45ms 안에 반복 호출하면 합칩니다. 상한에 도달하면 새 음을 생략합니다. 음악과 효과음은 별도 상한이므로 효과음 폭주가 BGM 자리를 빼앗지 않습니다.

v0.1.1은 BGM 0.85·SFX 1.15·마스터 0.9를 사용했지만, 재시험에서 여전히 매우 작다는 피드백을 받았습니다. [이슈 #16](https://github.com/ChoiDaeYoung-94/Pawblossom-Puzzle/issues/16)에서 BGM 4·SFX 3.4·마스터 1로 높이고, 노트가 시작하자마자 감쇠하던 처리를 BGM 100ms·효과음 25ms 유지 후 감쇠로 조정했습니다. 이전 자체 선율과 8종 음형을 유지하며 외부 음원을 추가하지 않았습니다.

출력은 버스 → 마스터 → 컴프레서 → 부드러운 포화 → 최종 피크 제한을 통과합니다. 컴프레서는 threshold -9dB·knee 6dB·ratio 6이며, 포화 단계는 작은 신호를 그대로 통과합니다. 4배 오버샘플링의 극단적 계단 입력에서 순간 피크가 1을 넘는 현상을 발견하여 최종 단계에 ±0.95 제한을 추가했습니다. 실제 검사한 음악·효과음·동시음 표본에서는 이 최종 제한에 도달하지 않았습니다. 모든 음향 왜곡이나 단말의 증폭을 없앤다는 뜻은 아닙니다.

### 2026-10-14 재현 가능한 출력 비교

`scripts/audio-output-qa.mjs`는 이전 커밋 `221a294`와 현재 AudioManager 코드를 실제 Chrome OfflineAudioContext에서 각각 실행합니다. 48kHz·2초·동일한 시나리오의 출력 RMS/피크를 비교합니다. 음악은 첫 박의 두 음이며 전체 루프 평균이 아닙니다. 겹침은 음악 6음·효과음 14음 상한에 도달하는 스트레스 표본입니다. 결과는 [원본 JSON](audio/louder-output-qa.json)에 남깁니다.

| 표본 | 이전 RMS | 새 RMS | 신호 RMS 증가 |
| --- | --- | --- | --- |
| 음악 첫 박 | 0.0205 | 0.1226 | +15.5dB |
| 탭 | 0.00158 | 0.00973 | +15.8dB |
| 교환 | 0.00736 | 0.0377 | +14.2dB |
| 매치 | 0.0102 | 0.0446 | +12.8dB |
| 특수 | 0.0203 | 0.0798 | +11.9dB |
| 승리 | 0.0288 | 0.1097 | +11.6dB |
| 동시음 상한 | 0.0468 | 0.1289 | +8.8dB |

8종 개별 효과음 모두 +11.6~15.8dB였고, 모든 표본에서 절대값 1 이상인 샘플은 0개였습니다. 겹침 피크는 0.872, 극단 입력의 최종 피크는 0.95였습니다. 이는 특정 디지털 신호의 측정값이며 사람이 느끼는 크기의 배수·LUFS·실제 휴대폰 청취 결과가 아닙니다.

로컬 재검사는 Playwright가 설치된 경로와 Chrome이 필요합니다. 게임 의존성과 필수 CI 환경은 늘리지 않습니다. Git에 비교용 이전 커밋이 있어야 합니다.

```powershell
. .\scripts\use-dev-tools.ps1
$env:PAWBLOSSOM_PLAYWRIGHT_MODULE='C:/Users/user/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules/playwright/index.mjs'
node scripts/audio-output-qa.mjs
```

실시간 Chrome에서도 BGM·특수 효과음의 신호, 두 옵션 OFF의 출력 0, suspend/resume의 suspended→running을 확인했습니다. 저장 설정·음성 상한·중단 시 예약 음 정리를 유지합니다. 음악·SFX 옵션을 끌 때 예약 엔벌로프를 취소하고 20ms 감쇠 뒤 25ms에 정리합니다. 배경 중단·파괴 시에는 음성을 즉시 정리합니다. 실제 스피커의 밸런스·피로도와 전화·이어폰 전환은 아래 실기기 점검으로 이어갑니다.

## 임시 음원으로서의 한계

합성 사인파는 작은 용량과 라이선스 명확성에 유리하지만 전문 녹음의 타건 질감·잔향·공간감은 부족합니다. 반복 청취 피로도와 저가 Android 스피커의 고음 자극은 아직 검증되지 않았습니다. 네이티브 오디오 포커스, 전화·Bluetooth 전환, 광고 SDK의 사운드 정책은 이 모듈만으로 완전히 제어할 수 없습니다. 이 구현은 시제품용이며 스토어 출시 품질을 확정한 음원이 아닙니다.

최종 음원을 새로 제작하더라도 현재 API와 사용자가 저장한 음악·효과음 설정을 유지합니다. 타 게임 음원을 추출하거나 가공해 교체하지 않습니다.

## 구현 시 확인한 범위

2026-10-08 기준 단독 AudioManager strict 타입 검사와 프로젝트의 `tsc --noEmit`이 통과했습니다. 별도 파일을 추가하지 않고 모의 Web Audio 환경에서 잠금 전 호출, 중복 unlock, 8종 효과음, 동시음 상한, 35초 스케줄 진행, 지연 프레임 건너뛰기, 설정 전환, suspend/resume, visibility와 명시적 pause 중첩, 중복 destroy 후 자원 정리를 확인했습니다. 이 검사는 실제 브라우저 오디오 출력이나 실기기 청취를 대신하지 않습니다.

Web Audio 동작 참고: [MDN AudioContext.resume](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/resume), [MDN AudioScheduledSourceNode.stop](https://developer.mozilla.org/en-US/docs/Web/API/AudioScheduledSourceNode/stop). 자동 재생 정책과 네이티브 생명주기 연결은 아래 실기기 검수로 확인해야 합니다.
