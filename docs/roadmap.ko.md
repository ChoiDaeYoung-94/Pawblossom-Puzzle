# 출시까지의 개발 순서

첫 단계는 TypeScript + Phaser + Capacitor 시제품입니다. 엔진을 바꾸지 않고 Android에서 실제 플레이 품질과 수익화 연동을 먼저 확인합니다. 세션은 6.1 Sol / Medium을 사용하고 작업 파일 범위를 분리합니다.

1. **첫 시제품 점검:** 교환·목표 수집·특수블록을 설명하는 3단계 안내를 추가했습니다([검증 기록](tutorial-qa.ko.md)). 고정 시드 자동 플레이를 비교하여 초반 3개 레벨의 이동 여유를 조정했습니다([난이도 기록](level-balance.ko.md)). 다음으로 실제 이용자 플레이에서 목표 이해도와 난이도를 확인하고, 직접 교환하는 실습 안내를 검토합니다. Android 터치·복귀·뒤로가기·무음 플레이를 점검합니다.
2. **게임 콘텐츠 보강:** 레벨 데이터를 별도 모듈로 분리했습니다. 다음으로 장애물 규칙을 하나씩 추가합니다. 핍의 표정·성공 반응, 화단 변화 아트, 특수블록의 범위 예고를 제작합니다. 신규 친구와 지역은 이 흐름이 검증된 뒤 확장합니다.
3. **수익화 검증:** 테스트 광고 ID로 선택형 보상 광고와 전환 시점 광고를 연결합니다. 광고 제거는 실제 Google Play 일회성 상품, 구매 검증·재설치 복원·취소·네트워크 실패 흐름으로 구현합니다. 제거 대상 광고와 보상형 광고 유지 여부를 상품 설명과 일치시킵니다.
4. **출시 준비:** 대상 연령에 맞는 광고·동의 흐름, 개인정보처리방침, 데이터 보안 설문, 콘텐츠 등급을 작성합니다. 업로드 키 관리와 서명 AAB, 스토어 영문·한국어 소개, 최종 이미지·사운드 검수를 완료합니다.
5. **테스트와 운영:** 내부/비공개 테스트, 저사양 Android 성능·배터리·오프라인·저장 복구·광고/구매 오류 검증 후 출시합니다. 출시 이후에는 실제 이탈 구간과 레벨 난이도를 근거로 보강합니다.

현재는 광고 SDK와 결제 SDK를 설치하지 않았으며, 관련 상품·광고 시청을 작동하는 것처럼 표시하지 않습니다. 광고·결제 단계에는 개발자 계정과 해당 서비스 설정이 필요합니다. 출시 날짜와 수익은 아직 확정하지 않습니다.
