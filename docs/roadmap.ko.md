# 출시까지의 개발 순서

첫 단계는 TypeScript + Phaser + Capacitor 시제품입니다. 엔진을 바꾸지 않고 Android에서 실제 플레이 품질과 수익화 연동을 먼저 확인합니다. 세션은 6.1 Sol / High을 사용하고 작업 파일 범위를 분리합니다.

첫 출시 준비 국가는 사용자님이 선택한 **한국·미국**입니다(2026-10-15). 어린이부터 중장년까지의 기획을 유지합니다. 운영 국가를 콘솔에 반영했거나 광고·결제 출시 검증을 끝낸 상태는 아닙니다. 수익화 SDK 후보·아동 보호·구매 복원과 다음 구현 순서는 [Android 도입 판단](android-release.ko.md#광고광고-제거-결제-도입-판단-이슈-51)에 기록합니다.

구체적인 미완료 항목과 기기·계정 의존 조건은 [출시 작업 체크리스트](release-checklist.ko.md)에 관리합니다. 개발 브랜치에 구현한 상태와 main 병합·실기기 검증·출시 상태는 구분합니다.

진행 중 일반 회차의 안정된 보드·낙엽·이동·수집·점수·무료 섞기는 같은 기기에 로컬 저장하고 재실행 또는 테스트 선택창의 일반 복귀에서 이어갑니다(이슈 #40). 연쇄 도중에는 직전 안정 상태를 보존하며, 종료 판정과 첫 보상을 결과창 전에 저장합니다. 손상되거나 레벨 구성이 달라진 회차만 폐기하고 기존 영구 기록은 유지합니다. 자동 검사 123개와 Chrome 시나리오 8개를 통과했으며, 실제 Android 종료·업데이트 복원과 클라우드/다른 기기 복원은 별도 미완료 범위입니다.

1. **첫 시제품 점검:** 교환·목표 수집·특수블록을 설명하는 3단계 안내와 별도 보드의 첫 교환 실습을 추가했습니다([실습 검증](practice-qa.ko.md)). 고정 시드 자동 플레이를 비교하여 초반 3개 레벨의 이동 여유를 조정했습니다([난이도 기록](level-balance.ko.md)). 다음으로 실제 이용자 플레이에서 목표 이해도와 난이도를 확인합니다. Android 터치·복귀·뒤로가기·무음 플레이를 점검합니다.
2. **게임 콘텐츠 보강:** 레벨 데이터를 별도 모듈로 분리했습니다. 낙엽 규칙과 겹 수 표현, 특수 범위 연출, 정원 0~5단계 자체 아트, 기존 핍 그림의 성공·재도전 반응을 추가했습니다. 30스테이지 초안과 10개 단위 선택을 구현하고 기존 10스테이지 완료 저장을 이어갑니다. 전용 표정 아트와 출시 콘텐츠 수는 별도로 확정합니다. 신규 친구와 지역은 이 흐름이 검증된 뒤 확장합니다.
3. **수익화 검증:** 한국·미국과 어린이 포함을 기준으로, 전체 요청에 아동 보호 설정을 적용한 Android 시험 광고 한 형식부터 검증합니다. 운영 mixed audience의 중립 연령 확인과 실제 데이터 처리 검수는 별도 필요합니다. 보상형·전면 광고는 어린이용 형식 조건과 게임 복귀를 확인한 뒤 적용 범위를 정합니다. 광고 제거는 Google Play 비소모성 일회성 상품의 구매 검증·pending·승인·재설치 복원·환불 갱신을 구현합니다. 제거 대상 광고와 보상형 광고 유지 여부를 상품 설명과 일치시킵니다.
4. **출시 준비:** 대상 연령에 맞는 광고·동의 흐름, 개인정보처리방침, 데이터 보안 설문, 콘텐츠 등급을 작성합니다. 업로드 키 관리와 서명 AAB, 스토어 영문·한국어 소개, 최종 이미지·사운드 검수를 완료합니다.
5. **테스트와 운영:** 내부/비공개 테스트, 저사양 Android 성능·배터리·오프라인·저장 복구·광고/구매 오류 검증 후 출시합니다. 출시 이후에는 실제 이탈 구간과 레벨 난이도를 근거로 보강합니다.

이슈 #54에서 Android debug 전용 GMA 25.4.0·UMP 4.0.0 브리지와 명시적 전면 시험 광고 요청·상태·게임 복귀를 구현했습니다. 자동 검사·브라우저 IPC 대역·Android 빌드를 통과했지만 실제 기기의 광고·동의 실행은 미검증입니다. 웹과 release에는 시험 진입이 없고 release AAB에는 광고 SDK가 포함되지 않습니다. 결제 SDK와 상품은 아직 구현하지 않았습니다. 운영 광고·결제에는 개발자 계정과 서비스 설정·기기/스토어 검증이 필요하며, 출시 날짜와 수익은 아직 확정하지 않습니다.

작은 수정마다 APK 테스트를 요청하지 않습니다. 자동 검사·브라우저 검증으로 중간 작업을 확인하고 콘텐츠·기능·안정성 작업이 묶음으로 쌓인 뒤 테스트 빌드를 제공합니다. APK 안내는 대화에 바로 적습니다.
