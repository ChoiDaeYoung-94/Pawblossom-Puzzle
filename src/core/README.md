# 퍼즐 엔진

`src/core/index.ts`에서 `BoardEngine`, `seededRng`와 관련 타입을 가져옵니다. 외부 런타임 의존성이 없는 동기 TypeScript 엔진입니다.

```ts
const engine = new BoardEngine(8, 8, seededRng(42));
const result = engine.swap({ row: 0, col: 0 }, { row: 0, col: 1 });
```

- 행·열은 각각 3 이상의 정수이며 기본 크기는 8×8입니다. kind는 0~5입니다.
- 새 엔진/회차는 `ruleVersion: 2`이며 같은 색 2×2 정사각형도 매치하여 기존 꽃폭탄(`bomb`) 하나를 만듭니다. 버전 없는 기존 snapshot은 `ruleVersion: 1`의 직선 규칙으로 복원합니다. 명시적인 구 규칙 생성은 다섯 번째 생성자 인자 `1`을 사용하며 미지원/서로 다른 복원 버전은 거절합니다. 저장할 때는 전역 최신 버전 대신 실제 `engine.ruleVersion`을 기록합니다.
- 생성 직후와 유효 교환 완료 후에는 매치가 없고 합법 이동이 있습니다.
- `findMatches()`는 해당 회차의 수평·수직 3개 이상과 V2의 2×2 정사각 좌표를 중복 없이 행 우선 순서로 반환합니다. 특수도 kind 매치에 참여합니다. 조회·교환·연쇄·낙엽 피해는 같은 패턴 판정을 사용합니다.
- `hasMoves()`는 보드를 변경하지 않습니다. `swap()`은 인접 좌표만 허용하고 무효 교환을 복구합니다.
- 4개 수평 매치는 row, 4개 수직 매치는 column, 5개 이상 직선은 rainbow, 교차된 T/L과 V2의 정사각은 bomb를 만듭니다. 같은 연결 그룹에서 하나만 생성하고 우선순위는 5직선 rainbow → 실제 교차 또는 정사각 bomb → 4직선 줄 특수입니다. 독립된 직선4 특수와 기존 조합/폭탄 범위는 유지합니다.
- 생성 위치는 교환 도착지 b, a, 교차점 또는 첫 매치 좌표 순으로 결정합니다. 기존 특수 타일을 생성 위치로 사용하지 않습니다.
- row는 한 행, column은 한 열, bomb는 중심 포함 3×3, 연쇄에 맞은 rainbow는 자신의 kind를 제거합니다.
- rainbow+일반은 상대 kind, rainbow+특수는 상대 kind를 같은 특수로 바꿔 발동, rainbow+rainbow는 전체 보드를 제거합니다.
- 줄+줄은 두 교환 위치의 행·열, bomb+bomb는 두 위치의 5×5, bomb+줄은 bomb 위치 중심 3개 행과 3개 열을 제거합니다. 특수와 일반의 교환은 매치 없이 발동합니다. `activate(p)`는 특수 탭이며 rainbow 탭은 자체 kind를 제거합니다.

## 단계 재생과 수집

`swap()`은 모든 연쇄를 처리하고 최종 보드를 즉시 반영합니다. UI는 반환된 독립 스냅샷을 재생합니다. 첫 `before`는 교환이 끝난 보드이므로 UI의 교환 애니메이션을 먼저 재생합니다.

각 단계는 `before` 표시 → `removed` 제거와 `created` 특수 생성 → `after` 낙하·보충 순서입니다. `created` 좌표는 낙하 **이전** 위치이며, 생성 타일은 제거되지 않고 생존 타일들과 함께 낙하합니다. 따라서 `after`에서 행 위치가 달라질 수 있습니다. 제거 목록은 중복이 없으며 생성 위치를 포함하지 않습니다. 보충 타일은 일반 타일입니다.

`collected[kind]`는 실제 제거된 원래 타일의 수입니다. 특수 생성 칸은 수집되지 않습니다. `score`는 단계별 제거 수 × 10 × 연쇄 단계 번호(1부터)에 완전히 치운 낙엽 더미당 20점을 더합니다.

`setLeaves(LeafPile[])`는 고정 바닥층을 설정하고 `remainingLeaves()`는 겹 수와 무관하게 남은 더미 수를 반환합니다. 타일 교환·낙하·섞기는 낙엽 위치를 바꾸지 않습니다. 같은 칸 또는 직교 이웃 매치로 한 단계마다 한 겹씩, 특수 효과가 직접 닿으면 모든 겹을 치웁니다. 일반 매치의 새 특수 생성 칸도 바닥 피해에 포함하며 같은 단계의 중복 피해는 한 번만 적용합니다.

바닥 피해가 있는 단계만 `leaves: {before, after, hits}`를 포함합니다. UI는 이 독립 스냅샷을 단계별로 재생합니다. `leavesCleared`는 한 이동에서 완전히 치운 더미 수이며 0이면 생략합니다. 열매 수집과 별개의 완료 목표로 사용합니다.

막힌 최종 보드는 자동으로 섞이며, `removed: []`인 추가 단계로 기록됩니다. 이 단계는 수집과 점수를 늘리지 않습니다. 공개 `shuffle()`을 직접 호출할 때는 UI가 전후 보드를 별도로 캡처합니다.

## 경계 조건

`board`는 공개이므로 테스트나 저장 복원 시 직접 설정할 수 있습니다. 크기, 타일 객체, kind 범위를 호출자가 유지해야 하며, 플레이 중 복원은 매치가 없는 안정된 보드를 사용해 주세요.

`shuffle()`은 최대 300회 타일과 특수를 보존해 섞습니다. 이 시도에서 안정된 이동 가능 보드를 찾지 못하면 일반 타일로 새 보드를 생성합니다. 동일 kind만 있는 보드처럼 보존과 매치 제거를 함께 만족할 수 없는 구성도 이 방식으로 복구합니다.

rng는 0 이상 1 미만의 유한수를 반환해야 합니다. 상수 rng 등 극단적인 입력에서도 초기 생성과 연쇄가 종료되도록, 생성 재시도 후 고정 패턴과 51번째 제거 단계 이후 해당 회차의 직선/정사각 매치를 피하는 보충을 사용합니다. 일반적인 난수에서는 자연스러운 무작위 보충을 사용합니다. V1의 초기 생성·조회·해소·섞기 난수 소비 순서는 보존하며 기준 `7ff7b07`의 실제 결과와 RNG golden으로 비교합니다.
